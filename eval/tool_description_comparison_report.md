# 工具描述对比实验记录

实验日期：2026-10-27。完整运行 31 道题、两个描述版本，共 62 次 Agent 执行。

本轮自动评分未显示准确率提升。两组均通过 30/31 题，工具调用相关指标一致；观察到新描述使天气和报告回答明确标注模拟数据。

## 实验控制

- before：修改前的七份工具描述，保存在 tool_descriptions_before.json。
- after：当前工具的“能力说明 + Args + Returns”描述，包含模拟数据能力说明。
- 工具实现、参数 schema、模型、系统提示词及知识库一致，每题共用一次路由结果。
- 两组逐题交替先后执行；城市、用户 ID 和月份采用相同的固定评测值。
- 耗时排除了公共路由分类，包含工具执行与最终回答生成。
- 单轮实验，未固定所有模型采样结果；RAG 内部生成也可能波动。

## 结果解释

两组唯一未通过的题目都是 rag_fault_001。工具调用和参数正确，但答案使用 Wi-Fi，评测要求子串 WiFi，导致关键词未命中。本次未修改评分规则，也未把它算成工具调用失败。

在涉及天气或使用记录的 11 道题中，最终答案提及“模拟”或“演示”的题数：修改前 0，修改后 8。这是本次事后文本检查，不是预先定义的质量评分，也不单凭词语出现就判定回答正确。

具体例子：weather_001 的旧答案直接陈述“北京今天的天气为晴天”；新答案说明“模拟天气数据，不代表今天的实际天气”。report_001 的新报告标注使用演示用户的模拟记录，旧报告没有这项说明。

平均耗时减少 0.927 秒，约 4.1%。单轮 API 延迟和生成长度均有波动，不能据此声称稳定提速。

## 当前评测的限制

- 只读检查确认当前 Chroma 的 agent 集合仅有 5 条片段，全部来自维护保养.txt。实验期间未修改知识库。故障与选购题缺乏足够参考资料，本轮不足以评价完整知识问答质量。
- 现有通过条件主要检查工具流程与关键词。回答“无法确定吸力下降的原因”也可能命中“吸力”，所以高通过率不等于问题真正解决。
- 本次同时改变描述结构与能力边界说明，不能单独归因于 Args / Returns 格式。
